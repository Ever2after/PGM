# P1 experiments

P1 adds a question-shared Normal effect to M1's wrong-answer concentration.
The independent and q-linked graphs have four and five parameters. The studies
then change the training loss, keeping the graph, bank and observation inputs
fixed, and separately test actual self-consistency stopping.

| Study | Design | Results | Command |
|---|---|---|---|
| Hierarchical CRP | [Model and controls](P1_HIERARCHICAL_CRP.md) | [Results](../results/hierarchical_crp/README.md) | `pgm hierarchical` |
| Joint / Prefix / Mixed | [Training objectives](P1_OBJECTIVE_ABLATION.md) | [Results](../results/p1_objectives/README.md) | `pgm p1-objective` |
| Next-answer NLL | [Predictive loss](P1_PREDICTIVE_ABLATION.md) | [Results](../results/p1_predictive/README.md) | `pgm p1-predictive` |
| Repair/damage NLL | [Transition loss](P1_TRANSITION_ABLATION.md) | [Results](../results/p1_transitions/README.md) | `pgm p1-transition` |
| Repair/damage Brier | [Brier loss](P1_BRIER_ABLATION.md) | [Results](../results/p1_brier/README.md) | `pgm p1-brier` |
| VOI / confidence stopping | [Stopping protocol](P1_STOPPING.md) | [Results](../results/p1_stopping/README.md) | `pgm p1-stop` |

The first five studies report fixed-prefix posterior and future forecasts.
Stopping reuses the frozen Joint/Mixed heads from the second study, independently
of the later loss experiments. Better fixed-prefix predictions do not establish
better stopping: the recorded P1 VOI variants do not improve M1's macro frontier.
These are exploratory comparisons on the previously inspected bank.

## Result snapshot

Git contains the six README/HTML reports and figures, aggregate CSVs, protocol
and validation records, parameters and selection records. The eight stopping
methods also have their standard per-cell results under
`results/v2/methods/p1_*`. The original v1/v2 results remain the baseline.

Local execution records (`cells/`, `locks/`, `run.json`), fine-grained
horizon/calibration tables and large prediction arrays are not
part of this snapshot. They contain local cache paths or repeat aggregate
outputs. Per-cell score intervals, paired contrasts, prefix scores and
MC/unique-correct sensitivity tables are included. A study's `run` command
generates the omitted files; `report` requires that completed run and its
prediction caches. The output lists in the individual design
documents describe those generated files as well as the committed snapshot.
The Hub download supplies the released **v2 banks/traces**, not P1 caches.

The numerical model, training and forecast code are preserved with their
recorded hashes. `objectives` and the four `diagnostics` helper modules are P1
dependencies; their separate M1/v1 diagnostic experiments are not included.

## Reproduce stopping with the frozen published heads

Run from the repository root with the package installed (`pip install -e .`).
Use a separate output directory so report generation preserves the snapshot
and the original v2 results:

```bash
pgm download --only v2
export PGM_RESULTS="$PWD/artifacts/p1-reproduction/results"
mkdir -p "$PGM_RESULTS/v2"
cp -R results/v2/cells "$PGM_RESULTS/v2/"

pgm p1-stop trace --workers 2
pgm v2 method --plugin examples/p1_stopping.py
pgm p1-stop report
```

The source heads remain the committed `results/p1_objectives/selection/`, as
specified in `configs/p1_stopping.json`. No refitting is needed for stopping.
New traces and locks use the current output paths and the original v2 baseline
files. They verify the frozen source code, fits, bank and baseline hashes.
This avoids reusing machine-specific cache paths or timestamps from the
original experiment. The focused report includes all eight stopping methods.

Optional combined v2 reports and plots use the existing interface and write
to the same isolated `PGM_RESULTS` directory:

```bash
pgm v2 report --methods p1_independent_joint p1_linked_joint p1_independent_mixed p1_linked_mixed
pgm v2 plot --methods M1 asc p1_independent_joint p1_linked_joint p1_independent_mixed p1_linked_mixed --out "$PGM_RESULTS/p1_stopping/figures/voi"
```

## Refit and evaluate the five training studies

With the same separate `PGM_RESULTS` directory and downloaded v2 banks, run in
dependency order. Each command fits, evaluates and exports its own report:

```bash
pgm hierarchical run --workers 2
pgm p1-objective run --workers 2
pgm p1-predictive run --workers 2
pgm p1-transition run --workers 2
pgm p1-brier run --workers 2
```

Later studies verify and reuse the preceding study's fits and predictions.
They need the preceding full `run`, rather than only the committed summary.
`fit` stops before test evaluation; `report` regenerates exports from a completed
run. `--models`, `--datasets`, `--workers`, `--out`, `--config` and `--overwrite`
are supported. Use the same `PGM_RESULTS` root across dependent stages;
`--out` alone does not relocate their baseline references. Training is CPU work
and includes all declared coefficient arms and numerical checks.

The stopping commands above continue to use the frozen published heads.
To evaluate newly fitted heads programmatically, pass a study dictionary with
the desired `source_dir` to `pgm_asc.p1_stopping.run.run`.

## Verification

```bash
pip install -e '.[test]'
OMP_NUM_THREADS=2 python -m pytest -q
```

Tests cover the existing v1/v2 pipeline, P1 nesting and gradients, quadrature,
label/suffix isolation, paired forecasting, exact transition probabilities,
all losses, stopping semantics, CLI dispatch and small fit/evaluate/report/resume
workflows. Generated test data and results use temporary directories.
